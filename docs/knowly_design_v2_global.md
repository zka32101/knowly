**自己申告の年齢を偽られるリスクの扱い**: 年齢の確認は自己申告で、偽ることを完全には防げない(中立方式の年齢確認の限界)。そのため、次の条件で全年代のリスクを下げる。
- Teen/Adult にも有害な内容は載せない(`sensitivity` が `adult-only` の雑学は v1.0 には含めない)。
- 広告、ユーザー間のやり取り(コメント・チャット・投稿)、位置情報、アカウント作成を持たない。
- 外部リンクは他アプリ紹介(Teen/Adult のみ)に限る。

## 1. 年代モード

### 1.1 4つの年代

| モード | 対象 | 読み方 | UI の特徴 |
|---|---|---|---|
| **Kids** | 就学前(3〜6歳) | 保護者と一緒に利用。文字は最小限 | 大きな絵・ボタン、音声読み上げ、1画面1トリビア、文字はひらがな(英語は短文) |
| **Junior** | 小学生(7〜12歳) | 自分で読む | 漢字を使わない表記(ふりがなは v1.1)、短文、○×クイズ |
| **Teen** | 中高生(13〜17歳) | 自分で読む | 標準の文章量、勉強・雑談タグ |
| **Adult** | 大人(18歳以上) | 自分で読む | 出典・信ぴょう性を表示、深掘り文、全機能 |

- 保護者・家族で使う場合は、保護者の端末で Kids モードに切り替えて子どもに渡す。
- モード切替は設定画面から。Kids への切替はいつでも可能、Kids から他モードへの切替は保護者ゲート(1.3)を通す。

### 1.2 年齢確認(ニュートラル・エイジゲート)
- 初回起動で「生まれた年」をスクロール選択(「何歳以上ですか」のような誘導質問にしない。年を選ばせる中立方式)。
- 年齢は**若いほうに見積もる**(誕生日が分からないため。年齢 = 今年 − 生まれた年 − 1)。結果に応じた初期モード:
  - 6歳以下 → Kids(保護者向け説明つき)
  - 7〜12歳 → Junior(保護者向け説明つき)
  - 13〜17歳 → Teen
  - 18歳以上 → Adult
  - 例: 2026年に2008年生まれを選ぶと 17歳として扱い Teen になる(安全側)。
- **生まれた年は保存しない**。保存するのは決まった年代(`ageBand`)だけで、端末内のみ。サーバーには送らない。
- 年代の変更は設定から行う。**Kids/Junior から他のモードへ変えるには保護者ゲート**を通す。Teen ↔ Adult の変更にはゲートを付けない(自己申告のため、年代で内容の危険度が大きく変わらない設計にする。上の「リスクの扱い」を参照)。

### 1.3 モード別の機能制限

| 機能 | Kids | Junior | Teen | Adult |
|---|---|---|---|---|
| アカウント | 不要(匿名) | 不要(匿名) | 匿名(任意でログイン) | 匿名/メール/Apple/Google |
| 広告 | なし | なし | なし | なし |
| 外部リンク(出典URL) | 非表示 | 保護者ゲート付き | 表示 | 表示 |
| シェアカード | なし | なし(保存のみ) | あり | あり |
| へぇ/使える/スゴイ評価 | あり(ローカルのみ) | あり | あり | あり |
| プッシュ通知 | なし | 保護者が許可した場合のみ | 任意 | 任意 |
| 課金(プレミアム) | 保護者ゲート | 保護者ゲート | あり | あり |
| 行動分析 | 無効 | 無効 | 同意取得後 | 同意取得後 |
| 音声読み上げ | 標準ON | 任意 | 任意 | 任意 |
| 評価の集計への反映 | なし | なし | あり | あり |

**v1.0 の実装上の簡略化**: シェアカード(画像)は未実装で、Teen 以上は本文の「コピー」のみ。通知は v1.0 では端末内のローカル通知(2.6)で、Kids/Junior はオフ。

**保護者ゲート**: 算数の計算(例: 「7 × 8 は?」を数字で入力)または長押し+質問。子どもが偶然通過しにくいが、保護者には簡単なもの。課金・外部リンク・設定変更・モード変更の前に表示する。

### 1.4 トリビアの年代別表現
同一の事実を年代ごとに書き分ける。

```
trivia/{triviaId}
{
  id, category, tags,
  minAgeBand: "kids" | "junior" | "teen" | "adult",   # 表示対象の下限
  levels: {
    kids:   { title, body, illustrationId, audioText },
    junior: { title, body },                          # 漢字を使わない表記(ふりがなは v1.1)
    teen:   { title, body },
    adult:  { title, body, source, sourceUrl, credibility }
  },
  ...(v1.0 の集計フィールドは維持)
}
```
- `levels` に無い年代へは、その上の年代の文を表示せず**配信対象外**にする(Kids に Adult の文を出さない)。
- 逆に下の年代向けの文は上の年代にも表示可(Adult が Kids 向けの易しい解説を読める)。ただし通常配信は自分の年代の `levels` を優先。
- 出典・信ぴょう性(★)・身近度は Teen 以上で表示。Kids/Junior では「ほんとかな？」確認マークのみ。

### 1.6 検索・フィルター・関心事(Junior〜Adult)
- **ライブラリ**: 年代・言語で配信できる全雑学を一覧する。検索は、ひらがな/カタカナ/全角半角/大文字小文字をそろえ、日本語と英語の両方の本文を対象にする(英語のことばで日本語の雑学も見つかる)。複数の語は AND。タイトルに一致するものを先に並べる。
- **フィルター**: ジャンル、シーン(Teen/Adult)、状態(保存済み / 知ってた / 知らなかった / 未評価)。同じ種類の中は OR、種類どうしは AND。
- **無料と鍵**: 無料の Teen/Adult は、日替わりの無料の日数ぶん・今日の関心のおすすめ・保存した雑学だけ開ける。それ以外は一覧に鍵が付き、タップでプレミアム案内。タイトルは見える(何があるかを示すため)。Kids/Junior とプレミアムはすべて開ける。
- **関心事**: ジャンル・シーン・キーワード(最大10個、1個20文字まで)を登録する。ホームの「あなたの関心」に、当てはまる雑学を日替わりで出す(無料2件、プレミアム5件。今日の雑学とは重複させない)。端末内にだけ保存し、送信しない。
- **絞り込みと関心事は別**: ホームの絞り込みは一時的な条件、関心事は登録して残る条件。Kids は一覧がないため、登録した「すきなもの」のジャンルで絞る。

### 1.5 コンテンツ年代別の掲載ルール
- Kids/Junior に出さないテーマ: 暴力・性・死・薬物・ギャンブル・政治・宗教の論争・恐怖を煽る話題・健康リスクの断定。
- 全トリビアに `sensitivity` タグ(`none` / `mild` / `adult-only`)を付与し、`adult-only` は Teen 以下に絶対配信しない。
- 公開前チェック: 全 Kids/Junior 向けコンテンツは人手でレビュー(自動判定のみで公開しない)。

## 2. 多言語・世界対応

### 2.1 対応言語ロードマップ

| フェーズ | 言語 |
|---|---|
| v1.0 | 日本語(ja)、英語(en) |
| v1.1 | スペイン語(es)、ポルトガル語-ブラジル(pt-BR)、フランス語(fr)、ドイツ語(de) |
| v1.2 | 中国語簡体(zh-Hans)・繁体(zh-Hant)、韓国語(ko)、インドネシア語(id)、ヒンディー語(hi) |
| v1.3 | アラビア語(ar、RTL)、トルコ語(tr)、ベトナム語(vi) |

優先順は ストアの市場規模と翻訳の確保しやすさから決めた仮置き。リリース後に DL 地域の実績で入れ替える。

### 2.2 UI のローカライズ
- Flutter の `flutter_localizations` + `intl`(ARB 形式)。`l10n/app_<locale>.arb`。
- 日付・数字・複数形(ICU message format)は intl に任せ、文字列連結で文章を作らない。
- **RTL 対応**を最初から設計に含める: `EdgeInsetsDirectional`、`AlignmentDirectional`、`Directionality` を使い、左右固定の記述を避ける(アラビア語は v1.3 だが、後付けは高コスト)。
- フォント: 日本語・中国語・韓国語・アラビア語・ヒンディー語は端末フォントに任せ、フォールバックを定義。Kids モードのひらがな表示は丸ゴシック系を同梱するか検討(同梱時はライセンス確認)。
- 文字サイズは端末設定に追従(`MediaQuery.textScaler`)。固定高のレイアウトを禁止。
- UI 言語とコンテンツ言語は別設定にできる(例: UI 英語・雑学を日本語で学ぶ)。既定は端末ロケール。

### 2.3 コンテンツのローカライズ
```
trivia/{triviaId}                   # 言語非依存: category, tags, minAgeBand, sensitivity, 画像
trivia/{triviaId}/translations/{locale}   # 言語別: levels(1.4 の本文)、reviewedBy、reviewStatus
```
- 配信クエリは `translations/{locale}` が存在し `reviewStatus == "published"` のものだけを対象にする。ユーザーの言語に翻訳が無い場合は英語にフォールバック。
- **ネタ選定の原則**: 一つの文化・国に依存しない普遍的な事実(科学・自然・宇宙・人体・動物・地理の事実・歴史の定説)を主軸にする。日本固有の話題(例: 日本の風習)は `regions: ["JP"]` を付け、該当地域のユーザーにのみ多く出す。
- **地域タグ**: `regions` を持たないものは全世界対象。国・文化によって不適切になり得る話題(宗教・政治・食文化・領土)は `sensitivity` と合わせて審査し、地域を限定する。
- 事実は地域によって定義が異なる場合がある(単位系: °C/°F、km/mile)。数値の単位は表示時に変換するか、両併記する。

### 2.4 翻訳ワークフロー
v1.0 の「AI 生成コンテンツ Won't」は、事実を新規に生成することを禁止する意味。翻訳は下記の運用で認める。

1. 日本語(または英語)で原文を作成・精査(出典つき)。
2. 機械翻訳で下訳。
3. **ネイティブ話者によるレビュー必須**(Kids/Junior は特に厳格)。`reviewStatus: draft → reviewed → published`。
4. 公開は reviewed 済みのみ。未レビューは配信しない。

**配信の仕組み(実装済み)**: 各翻訳に `reviewStatus`(draft / reviewed / published)があり、**リリースビルドは draft を配信しない**(`kAllowDraftContent`。デバッグビルドでは draft も表示)。ネイティブ話者・事実確認が済んだものを `reviewed` に変えて初めてリリースビルドに出る。

レビュー担当は初期は個人で確保できる言語(ja/en)から開始し、それ以外は外注またはクラウドソーシング。1本あたりの翻訳レビュー費用を見積もり、言語追加は費用が確定してから行う。

### 2.5 タグ(利用シーン)の世界対応
v1.0 の「飲み会」は日本的な文脈で、国・年代によっては不適切(飲酒の推奨と受け取られる)。以下に再定義する。

| v1.0 | v2.0 | 備考 |
|---|---|---|
| 飲み会 | **友だちと**(With friends) | 全年代で使える。飲酒を連想させない |
| こども向け | **こどもと**(With kids) | 保護者向けの視点。Kids/Junior モード自体とは別物 |
| ビジネス | **仕事で**(At work) | Adult/Teen のみ |
| 家族 | **家族と**(Family) | |
| 勉強 | **学びたい**(Learning) | |

- Kids/Junior モードでは利用シーンフィルターを出さず、年代と興味カテゴリー(動物・宇宙・からだ・のりもの・しぜん など絵で選べるもの)のみにする。

### 2.6 配信とタイムゾーン
- 雑学はアプリに同梱し、「今日の雑学」は**端末の現地日付**から端末内で決める(世界の各地で日付が分かれる。サーバー不要)。
- 毎日の通知は **端末内のローカル通知**で行う。端末の現地時刻・タイムゾーンで動くため、タイムゾーン処理も FCM トークンの管理も要らない。通知の既定は Teen/Adult でオフ(許可を求めてからオン)、Kids はなし、Junior は保護者が許可した場合のみ。
- v1.0 のランキング・サーバー集計はなし。「へぇ」の評価は端末内のみ。v1.1 以降にサーバー集計を入れる場合は、UTC 日曜 00:00 に統一し、言語ごとに別集計する(日本語のランキングを英語ユーザーに見せない)。

### 2.7 課金の世界対応
- RevenueCat のオファリングで地域別価格(ストアの価格ティア)を使用。通貨・金額は端末のストア表示に従い、アプリ内に固定金額を書かない。
- 購入の無料トライアルを使う場合、ストア表示の文言規定に従う(自動更新・解約方法の明記)。
- 価格・プランの中身は **2.8 マネタイズ(競合調査に基づく)** に従う。

### 2.8 マネタイズ(競合調査に基づく見直し)

| 〃 | Erudite(Fact of the Day) | 年 $19.99 |
| 〃 | Factorium(歴史の豆知識) | 年 $19.99(年額の特別価格 $9.99) |
| 〃 | FactWorld | 月 $9.99 / 年 $25.99、7日間無料 |
| 〃 | Daily Fun Facts | 年 $29.99〜$39.99、買い切り $44.99 |
| 子ども向け学習 | Khan Academy Kids | 無料(広告・課金なし) |
| 〃 | Duolingo ABC | 無料(広告なし・アプリ内課金なし) |

**読み取れること**
1. 雑学アプリの年額は **約 $10〜$40 で、中心は $20 前後**。v1.0 の月¥300(年換算 約3,600円 ≒ $24)は妥当な帯。レビューにあった¥500〜¥700(年換算 約6,000〜8,400円 ≒ $40〜$55)は、競合の上限を超える。
2. **子ども向けの最大手は無料で広告もない**。Kids/Junior を有料で囲うと競合に負け、子ども向け規約のリスクも高まる。
3. 月額で高く設定しているアプリ(FactWorld の月 $9.99)は年額との差が大きく、割高に見える。

**v2.0 の方針**

| 項目 | 内容 |
|---|---|
| 無料(全員) | **Kids/Junior の全コンテンツ**(広告なし。表示は日替わりの30日分ローテーション)、Teen/Adult は今日のトリビア+過去7日分、保存20件まで、通知、へぇ評価 |
| プレミアム(Teen/Adult 向け) | 過去30日分(無料は7日)、保存無制限。以降の段階で、全バックカタログのライブラリ、深掘り解説、オフライン保存、シェアカードのロゴ除去、週ピック集 |
| 価格(案) | 月 $1.99 / 年 $14.99(約2か月ぶんお得)、7日間無料トライアル |

## 3. 子ども向け規約・プライバシー対応

> 本章は設計上の要件を整理したもの。法的助言ではない。リリース前に各規約の最新版を確認し、必要なら専門家のレビューを受ける。

### 3.1 適用される主な規約・法令
- **COPPA(米国)**: 13歳未満の個人情報の収集には保護者の検証可能な同意が必要。
- **GDPR / GDPR-K(EU・英国)**: 子どものデータ処理の同意年齢は国により13〜16歳。
- **日本の個人情報保護法**: 子どもの個人情報は親権者の同意が実務上必要。
- **Apple App Store**: Kids カテゴリーの要件(第三者の広告・分析の禁止、保護者ゲート、外部リンク・購入の制限)。
- **Google Play ファミリーポリシー**: 子どもを対象に含むアプリへの要件(認定済み広告 SDK のみ、年齢に適した内容、データ収集の制限、「Designed for Families」)。

### 3.2 設計方針: データを取らない
子ども対応の最も確実な方法は、**13歳未満の個人データを収集しないこと**。

- Kids/Junior モードは Firebase 匿名認証または認証なしで動かし、メール・氏名・位置情報・連絡先を一切取得しない。
- 端末内のみに保存: 年齢、お気に入り、評価、閲覧履歴(sqflite / shared_preferences)。
- クラウドに送るのは、必要最小限の匿名データのみ(FCM トークンは、通知を使う Junior のみ・保護者許可後)。
- **広告なし**: 全モードで広告 SDK を入れない(収益はプレミアム購読のみ)。
- **分析**: Firebase Analytics は Kids/Junior では**初期化しない**(`setAnalyticsCollectionEnabled(false)`)。広告 ID(IDFA/AAID)の収集を無効化し、`AD_ID` 権限を Android マニフェストから除外。
- **SDK 監査**: 使う SDK(Firebase、RevenueCat、Lottie など)が各ストアの子ども向け要件に適合するか、リリース前に公式の一覧・ドキュメントで確認する。適合しない SDK は Kids/Junior モードで無効化できる構造にする。

### 3.3 同意の取得(Teen・Adult)
- 13〜15歳(EU の同意年齢未満): 保護者の同意が必要な地域がある。Teen モードでも**データ取得をしない設計(3.2 と同じ)を既定**とする。**v1.0 では Teen にログイン・分析を提供しない**。将来入れる場合も、16歳以上(または地域ごとの同意年齢以上)でのみ有効化。
- Adult: 分析・通知・ログインはオプトイン。同意画面は地域ごとの要件に従う(EU は CMP/同意管理を実装、同意前はトラッキング無効)。
- iOS: ATT(App Tracking Transparency)は、トラッキングを行わない設計なら不要。トラッキングを行う場合のみダイアログを実装。
- 「データ削除」: 設定からアカウント・サーバー上のデータを削除できる機能を用意(Apple・Google・GDPR 要件)。アカウントを作った場合に限る。

### 3.4 認証の変更
- **v1.0 は認証なし**(端末内で完結)。以下は v1.1 以降でクラウド同期を入れる場合の方針。
- 標準は **Firebase 匿名認証**。端末ごとの匿名 UID に、評価・保存データを紐付ける。
- 18歳以上のみ、任意で Apple / Google / メールにアップグレード(匿名アカウントとリンク)。他のソーシャルログインを提供する場合、iOS は「Sign in with Apple」の提供が必要。
- v1.0 の「メール+パスワード必須」「email を保存」を削除。`users` には年齢・メールを保存しない(Adult でログインした場合のみ email を保持)。

### 3.5 Firestore ルール・データモデル変更(v1.1 以降。v1.0 は端末内の SharedPreferences のみ)
```
/users/{uid}   # 匿名UID。個人を特定する項目を持たない
{
  ageBand: "kids" | "junior" | "teen" | "adult",   # 生年そのものは保存しない
  uiLocale, contentLocale, timezone, notifyTime,
  selectedFilters, selectedCategories,
  isPremium, premiumExpiresAt,
  fcmToken            # Teen以上、または Junior で保護者許可時のみ
}
```
- 評価の集計(`evaluations`)は Teen 以上のみ書き込み可(ルールで `ageBand` を検証)。Kids/Junior の評価は端末内のみ。
- `trivia` は全員読み取り可、書き込みは管理者(Cloud Functions / 管理ツール)のみ。v1.0 の `allow write: if request.auth.uid == null` は、未認証ユーザーなら誰でも書き込めてしまう設定になっているため、**`allow write: if false`**(管理側は Admin SDK から書くのでルールの対象外)に修正する。

### 3.6 ストア申請上の設定
- **Apple**: 年齢制限(App Store 年齢区分)を質問票で回答。Kids カテゴリーに入れるか(5歳以下・6〜8歳・9〜11歳)は、全機能が要件を満たす場合のみ。混在(家族+大人)アプリとして Kids カテゴリー外で出す方針も検討(下記 3.7)。
- **Google**: 「ターゲットとするユーザー層」に子ども(13歳未満)を含めるかを宣言。含める場合はファミリーポリシー全体が適用される。
- **IARC 年齢区分**: 質問票で回答。トリビアの内容(暴力・性・薬物の言及)が Teen/Adult で出る場合、その内容を正直に申告。
- **データセーフティ(Google)・プライバシーラベル(Apple)**: 収集項目を実装と一致させて申告(匿名 ID、クラッシュ、購入情報など)。
- **プライバシーポリシー・利用規約**: 日本語・英語を最初から用意し、対応言語に合わせて追加。子どもの扱い(収集しない旨)・保護者の連絡先・削除方法を明記。

### 3.7 提供形態の選択肢
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A: 1アプリ(混在)** | 1つのアプリに年代モード。Kids カテゴリー外で出す | 開発・運用が1本、家族で共有しやすい | 「子どもを対象に含む」ため、全モードで子ども向け要件の遵守が必要 |
| **B: 2アプリ** | Knowly(Teen/Adult)と Knowly Kids(Kids/Junior)を分ける | Kids をストアの Kids 区分に最適化できる、大人向け機能に制約を掛けない | 運用・審査・ストア掲載が2倍 |

**決定: A(1アプリ)**。A でも 3.2 の方針(広告なし、個人情報を取らない、分析を子どもで無効)は全モード共通で守る。収益が大人向けで伸びたら B に分離を検討。

### 3.8 他アプリ紹介(`cross_promo_kit`)
- **Teen/Adult の設定画面のみ**で表示する。Kids/Junior では表示せず、Firebase の初期化・通信もしない(設定画面を開いたときに初めて初期化。子どもモードでは呼ばない)。
- 紹介はストアへの外部リンクなので、子ども向けの規約上、Kids/Junior には出さない(出す場合は `isChildDirected: true` と保護者ゲートが必須)。
- `firebase_core` / `firebase_remote_config` はアプリに含まれる。**子どもを対象に含むアプリでは、含まれる SDK 自体も各ストアの要件の対象になり得る**ため、リリース前に Apple・Google の最新の要件と SDK の適合を確認する(6 のチェックリスト)。適合を確認できない場合は、他アプリ紹介を v1.0 から外す(影響は設定画面の1セクションのみ)。
- Firebase の設定ファイルがない環境では、初期化に失敗しても何も表示せず、アプリは動く。

### 3.9 既知のリスク
- **読み上げ(端末内 TTS)**: 端末に日本語・英語の音声データが入っていないと、読み上げボタンを押しても無音になる。v1.1 で音声の有無を検知し、ない場合は案内を出す。
- **自己申告の年齢**: 上の「自己申告の年齢を偽られるリスクの扱い」を参照。
